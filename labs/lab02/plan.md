## Часть 2 — Базовая настройка git

Выполни все команды по очереди:

```bash
git config --global user.name "Name Surname"
git config --global user.email "твой_email"
git config --global core.quotepath false
git config --global init.defaultBranch master
git config --global core.autocrlf input
git config --global core.safecrlf warn
```

Проверь что всё сохранилось:

```bash
git config --list
```

📸 **СКРИН: вывод git config --list — должны быть видны все настройки**

## Часть 3 — Создание SSH ключей

### 3.1 Ключ RSA

```bash
ssh-keygen -t rsa -b 4096
```

На вопросы нажимай **Enter** (оставляй всё по умолчанию)

📸 **СКРИН: вывод команды генерации RSA ключа**

### 3.2 Ключ Ed25519

```bash
ssh-keygen -t ed25519
```

На вопросы нажимай **Enter**

📸 **СКРИН: вывод команды генерации Ed25519 ключа**

### 3.3 Проверь что ключи созданы

```bash
ls ~/.ssh/
```

📸 **СКРИН: вывод команды — должны быть файлы id_rsa, id_rsa.pub, id_ed25519, id_ed25519.pub**

### 3.4 Добавь SSH ключ на GitHub

Выведи публичный ключ:

```bash
cat ~/.ssh/id_ed25519.pub
```

📸 **СКРИН: вывод команды с ключом**

Скопируй весь вывод целиком.

Затем:

1. Зайди на **github.com** → войди в аккаунт
2. Нажми на аватар → **Settings**
3. В левом меню → **SSH and GPG keys**
4. Нажми **New SSH key**
5. В поле **Title** введи например `ed25519`
6. В поле **Key** вставь скопированный ключ
7. Нажми **Add SSH key**

📸 **СКРИН: страница GitHub с добавленным SSH ключом**

## Часть 4 — Создание PGP ключа

### 4.1 Генерация ключа

```bash
gpg --full-generate-key
```

На вопросы отвечай так:

- **Тип ключа:** выбери `1` (RSA and RSA)
- **Размер:** введи `4096`
- **Срок действия:** введи `0` (не истекает)
- Подтверди: `y`
- **Имя:** введи своё имя (минимум 5 символов)
- **Email:** введи тот же email что указал в git config
- **Комментарий:** можно оставить пустым, нажми Enter
- Подтвердить: нажми `O` (Okay)
- Введи пароль для ключа (можно оставить пустым, нажав Enter дважды)

📸 **СКРИН: вывод после успешного создания ключа**

### 4.2 Посмотри список ключей

```bash
gpg --list-secret-keys --keyid-format LONG
```

📸 **СКРИН: вывод команды — запомни строку после "rsa4096/" это и есть fingerprint**

Вывод будет выглядеть примерно так:

```
sec   rsa4096/XXXXXXXXXXXXXXXX 2024-01-01 [SC]
      YYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYY
uid   [  абсолютно  ] Name Surname <email@mail.com>
```

`YYYYYYYY...` — это и есть твой **PGP Fingerprint** (длинная строка)

### 4.3 Экспортируй ключ

```bash
gpg --armor --export ВСТАВЬ_СВОЙ_FINGERPRINT
```

📸 **СКРИН: вывод команды — длинный текст начинающийся с "-----BEGIN PGP PUBLIC KEY BLOCK-----"**

Скопируй весь вывод целиком включая строки BEGIN и END.

### 4.4 Добавь PGP ключ на GitHub

1. Зайди на **github.com** → **Settings**
2. В левом меню → **SSH and GPG keys**
3. Нажми **New GPG key**
4. Вставь скопированный ключ
5. Нажми **Add GPG key**

📸 **СКРИН: страница GitHub с добавленным GPG ключом**

```bash

```

Утилита задаст вопросы — отвечай так:

- **What account do you want to log into?** → `GitHub.com`
- **What is your preferred protocol for Git operations?** → `SSH`
- **Upload your SSH public key to your GitHub account?** → выбери свой ключ `id_ed25519.pub`
- **How would you like to authenticate GitHub CLI?** → `Login with a web browser`

Скопируй одноразовый код который появится в терминале, нажми Enter — откроется браузер, вставь код и подтверди.

📸 **СКРИН: вывод gh auth login с подтверждением успешной авторизации**

Проверь авторизацию:

```bash
gh auth status
```

## Ответы на контрольные вопросы

**1. Что такое системы контроля версий (VCS)?**
VCS — программный инструмент для отслеживания изменений в файлах проекта. Позволяет фиксировать изменения, возвращаться к предыдущим версиям, работать нескольким разработчикам над одним проектом без конфликтов.

**2. Хранилище, commit, история, рабочая копия:**

- **Хранилище (репозиторий)** — место где хранятся все версии файлов и история изменений
- **Commit** — зафиксированный снимок состояния файлов в определённый момент с описанием изменений
- **История** — последовательность всех коммитов с указанием автора, даты и описания
- **Рабочая копия** — текущее состояние файлов на локальном компьютере, с которым работает разработчик

**3. Централизованные и децентрализованные VCS:**

- **Централизованные** — единый сервер хранит все версии, разработчики получают рабочую копию с него. Примеры: CVS, Subversion (SVN)
- **Децентрализованные** — каждый разработчик имеет полную копию репозитория локально. Примеры: Git, Mercurial

**4. Единоличная работа с VCS:**

```
git init → создать репозиторий
git add . → добавить файлы
git commit -m "message" → зафиксировать изменения
git log → просмотреть историю
```

**5. Работа с общим хранилищем:**

```
git pull → получить изменения с сервера
# внести изменения в файлы
git add .
git commit -m "message"
git push → отправить изменения на сервер
```

**6. Основные задачи git:**
Отслеживание изменений файлов, ведение истории версий, работа с ветками, слияние изменений от разных разработчиков, откат к предыдущим версиям.

**7. Команды git:**

| Команда                  | Описание                         |
| ------------------------ | -------------------------------- |
| `git init`               | Инициализация репозитория        |
| `git clone <url>`        | Клонирование репозитория         |
| `git add .`              | Добавить все изменения в индекс  |
| `git commit -m "msg"`    | Зафиксировать изменения          |
| `git push`               | Отправить на сервер              |
| `git pull`               | Получить с сервера               |
| `git status`             | Статус рабочего каталога         |
| `git log`                | История коммитов                 |
| `git branch`             | Список веток                     |
| `git checkout -b branch` | Создать и переключиться на ветку |
| `git merge branch`       | Слить ветку                      |

**8. Примеры работы с репозиторием:**

Локальный:

```bash
git init
echo "hello" > file.txt
git add file.txt
git commit -m "first commit"
```

Удалённый:

```bash
git remote add origin git@github.com:user/repo.git
git push -u origin master
git pull
```

**9. Зачем нужны ветки (branches):**
Ветки позволяют разрабатывать новую функциональность или исправлять баги изолированно от основного кода. После завершения работы ветка сливается с основной. Это предотвращает попадание незаконченного кода в рабочую версию.

**10. Игнорирование файлов при commit:**
Создаётся файл `.gitignore` в корне репозитория, в котором перечисляются шаблоны файлов которые не нужно отслеживать:

```
*.log
*.tmp
node_modules/
build/
```

Это нужно чтобы временные файлы, скомпилированные артефакты и конфиденциальные данные не попадали в репозиторий.
